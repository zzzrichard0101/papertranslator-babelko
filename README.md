# BabelKO · 한국어 PDF 번역기

PDFMathTranslate-next의 클라이언트·번역기 인터페이스와 BabelDOC의 문서 분석·배치·조판 엔진을 결합한 별도 Windows 실험판입니다. 기존 PaperTranslator 프로그램과 작업 기록은 그대로 유지합니다.

현재는 로컬 Qwen 27B를 사용합니다. 설치된 모델·CUDA 런타임의 경로와 SHA256을 별도 설정에 가져와 공유하며 기존 설정은 변경하지 않습니다. API 키 없이 실행합니다.

## 실행

현재 개발 PC에는 별도 환경과 바탕화면 `BabelKO 한국어 PDF 번역기 (실험판)` 바로가기가 설치되어 있습니다. 소스 실행:

```powershell
uv run python -m babelko
```

새 환경에서는 먼저 `scripts/setup.ps1`로 고정된 두 상위 저장소·Python 의존성·폰트·배치 모델·영어 OCR을 준비해야 합니다. 초기 자산 준비에는 인터넷이 필요합니다. 기존 로컬 모델 저장소가 없는 PC의 모델 다운로드 UI는 아직 구현하지 않았습니다.

명령줄:

```powershell
uv run python scripts/translate.py input.pdf --output results --pages 1-5,9 --ocr auto
```

결과 폴더는 미리 생성해야 합니다. 쪽 번호는 PDF의 물리 쪽이며 비우면 전체를 처리합니다.

## 현재 동작

- BabelDOC의 배치 인식·문단·수식·스타일 처리와 열/쪽 경계 번역 경로 사용
- 한국어 PDF와 같은 원문 쪽을 왼쪽에 유지한 대조본 생성
- 선택 쪽의 스캔만 로컬 OCR. 검색용 글꼴 대신 실제 글꼴의 줄을 복원한 입력 사본으로 처리
- 배치 ID·빈 번역·숫자/부호/출현 수·수식과 스타일 자리표시자 검사. 배치 및 단일 문단 fallback에 동일 검사 적용
- 올바른 영어 분수 표현과 한국어 수량 동치 처리. 실패 후보는 제한된 재요청 후 실패 근거 보존
- 원본 해시·입력 해시·모델 스냅샷·원응답·중간 번역 기록 보존. 취소 후 재시작은 동일 입력 캐시를 활용하고 분석/조판은 다시 수행
- 완료 판단은 실제 BabelDOC 작업의 반환값을 사용. 최종 번역 검사 실패를 완료로 표시하지 않음
- 자산 준비 후 worker 외부 DNS/연결 차단, 인증된 루프백 모델 서버만 사용

## 검증과 범위

검증 결과는 로컬 `work/`와 `test_vault/`에 기록합니다. 단위 검사 43개와 실제 BabelDOC/OCR/조판을 사용하는 합성 통합 검사가 통과했습니다. 실제 로컬 모델로 2단 논문의 선택 2쪽과 합성 스캔 표 1쪽을 시험했습니다. 합성 번역 응답 검사는 실제 모델 의미 정확도 평가와 구분합니다. 재현 범위는 `DEVELOPMENT.txt`에 기록합니다.

현재는 초기 0.1 실험판입니다. 모든 문서에서 의미 오류·OCR 누락이 없어졌다는 검증은 없습니다. 검증된 범위는 선택된 2단 논문 쪽과 흰 배경 영어 인쇄체 스캔입니다. 색 배경/손글씨/복잡한 도식/병합 표와 장문 장애 복구는 추가 검증이 필요합니다. 스캔 입력은 OCR 글자를 실제 폰트로 재구성하므로 원문의 정확한 글꼴·이미지 조판과 같지 않습니다. 대조본의 원문 면은 원본을 사용합니다.

기존 앱의 다중 모델 교정·무료 API·Obsidian·전체 고급 검수 기능은 아직 이식하지 않았습니다. 새 엔진의 전체 문서 속도·의미 품질 우위를 보증하지 않으며 캐시 사용 시간과 새 번역 시간을 구분합니다.

## 개발 검사

```powershell
uv run pytest -q
uv run python scripts/integration.py
```

두 저장소의 최신 요구 버전은 서로 다릅니다. 전체 상위 WebUI 대신 실제 사용 API에 필요한 의존성만 별도 환경에 고정했으며 `upstream.lock.json`의 커밋과 `uv.lock`을 사용합니다. 한국어 글꼴 별칭과 진행 콜백의 완료 경쟁을 연결부에서 보정합니다. 자세한 구성은 `docs/ARCHITECTURE.txt`에 기록합니다.
