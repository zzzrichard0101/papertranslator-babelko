전체 파이프라인 효율 점검 (2026-10-21)

원칙
번역·검수 내용을 줄여 시간을 맞추지 않는다. 동일 입력의 중복 작업과 불필요한 모델/디스크 작업을 제거한다. 원문·문맥이 바뀐 검수는 재사용하지 않는다. 사용자 PDF나 번역문은 직접 수정하지 않는다.

단계별 점검 및 반영
1. 입력·무결성: 원본, OCR 입력, 가중치와 결과 해시 검사는 유지한다. 큰 파일의 해시 확인을 파일 날짜만으로 대체하지 않는다.
2. 최초 OCR: 처리된 쪽을 원본/구현/모델/쪽 좌표에 묶어 즉시 저장한다. 재개 시 검증된 쪽만 가져온다. 영어 OCR 데이터 해시는 필요한 실행당 한 번 확인한다. 최종 입력과 쪽 캐시는 무손실 압축으로 저장한다. 기존 사용자 작업의 Input.pdf는 재작성하지 않는다.
3. 보완 OCR: 위험 영역 판독과 쪽별 캐시는 유지한다. CPU 두 프로세스 처리를 실측했으나 더 느려 기본값으로 채택하지 않는다. GPU를 OCR에 배정하지 않는다.
4. PDF 분석: 번역 전 native IL을 JSON 그래프로 저장한다. 글자·서식 객체의 공유 참조와 쪽 사이 참조를 보존한다. 원본 입력, 준비된 PDF의 모든 xref/stream, 분석 설정, 고정 상위 버전과 어댑터 코드가 일치할 때만 재사용한다. 손상/다른 입력/지원하지 않는 설정은 원래 분석으로 돌아간다. 실행 가능한 역직렬화 형식은 쓰지 않는다.
5. 초벌 수집: 버릴 IL 위에서 원문 단위를 수집한다. 실제 초벌 출력은 별도 체크포인트에 저장한다. 저장된 최종 번역과 초벌의 길이 차이가 상위 엔진의 임시 분기를 바꾸지 않도록 한다. 최종 재적용에는 실제 검증된 한국어만 사용한다.
6. 검수 목록: 이전 원문 목록 순서를 보존하여 스레드 완료 순서 차이만으로 주변 문맥과 캐시가 바뀌지 않도록 한다. 실제 단위가 추가/삭제되거나 문맥이 바뀌면 기존의 정확한 입력 검사에 따라 새로 검수한다.
7. 모델 로딩: CPU 분석이나 캐시 전용 경로에서 모델을 로딩하지 않는다. 각 단계의 첫 실제 요청 직전에 인증된 로컬 클라이언트를 연결한다. 완전 캐시 재개는 모델 로딩 0회가 가능하다. 초기화는 잠금으로 보호한다.
8. 모델 추론: 검증했던 MTP, 압축 응답, 소규모 검수 묶음과 보수적인 근거 재사용을 유지한다. 문장·수식·숫자·부정·조건 검사를 제거하지 않는다. 한 GPU에서 두 대형 모델 동시 상주는 적용하지 않는다.
9. 저장: 마지막 성공 기록과 같은 체크포인트를 다시 쓰지 않는다. 변경/실패한 저장은 생략하지 않는다. 진행 표시만 최대 0.5초 간격으로 묶고 상태 변경·실패·완료는 즉시 저장한다.
10. PDF 출력·검사: 무손실 최적화와 원문 대조면 생성, 쪽 개수·넘침·문자 손상·본문 생존 검사를 유지한다. 같은 출력의 텍스트 페이지를 검사 사이에 재사용하여 중복 글자 추출을 제거한다.
11. 관측: performance.json에 실행별 단계 시간, 분석/캐시/모델 로딩/추론/출력 시간, 요청 수와 토큰 수를 자동 기록한다. 단계 시간과 내부 구성 시간은 겹칠 수 있어 합산하지 않는다. Quality.json에도 요약을 포함한다.

측정·검증
- 쪽 OCR 중단 후 재개와 새 처리 결과의 추출 단어/좌표/렌더 픽셀 일치 검사.
- 실제 BabelDOC의 단일/결합 경로에서 분석 캐시를 사용한 재개를 강제로 실행. 새 모델 요청·로딩 없이 결과의 단어/좌표/렌더 픽셀이 같은지 검사. 캐시의 공유 글자/서식 참조, 손상 및 설정 불일치도 검사.
- CPU OCR 8쪽: 직렬 22.502초, 두 프로세스 26.813초. 32쪽: 79.148초, 93.810초. 출력 글자·좌표·신뢰도는 같았지만 병렬 기본값은 거부했다. 같은 PC에서 진행 중인 다른 작업이 있는 합성 인쇄체 표본이므로 모든 CPU의 결과로 일반화하지 않는다.
- 앞선 실제 Qwen 교정 대조는 해당 독립 문장 교정 구간에서 요청 4→2회였으며, 부정·수량 변경은 전체 검수를 유지했다. 전체 책 속도 단축률과 구분한다.

적용 범위
이미 실행 중인 worker의 코드를 중간에 바꾸지 않는다. 새 worker, 새 번역 및 같은 체크포인트 재개에 새 코드가 자동 적용된다. 현재 진행 중인 문서를 속도 개선만을 이유로 거듭 재시작하지 않는다. 분석 캐시는 처음 한 번 생성되어야 다음 재개에서 활용된다. 새 입력·새 문맥의 실제 OCR/번역/검수 추론은 필요하다. 모든 문서의 최저 시간이나 무오류 의미 정확도를 보증하지 않는다.
