OCR 입력 검증 (2026-10-24)

목적
번역 결과에 남은 글자를 검사하는 기존 절차는 OCR이 원본에서 놓친 글자를
발견하지 못한다. scripts/audit_ocr_corpus.py는 원본 이미지에서 독립적으로
확인한 텍스트와 번역 전 Input.pdf를 쪽과 좌표 영역별로 비교한다. 원본 SHA-256과
쪽 수를 확인하고, 같은 단어가 반복될 때도 개수를 세어 누락을 보고한다.
OCR 출력 자체나 번역문을 정답으로 사용하지 않는다.

실행
  .\.venv\Scripts\python.exe scripts\accuracy_corpus.py prepare
  .\.venv\Scripts\python.exe scripts\audit_ocr_corpus.py --base test_vault\accuracy-diverse-20261021 --prepare --output test_vault\ocr-audit.json

--prepare는 번역 작업과 분리된 OCR 입력을 만들며, 원본·코드 버전·선택 쪽과
생성 입력의 해시를 검사한다. 코드나 입력이 바뀌면 다시 실행해야 한다.
tests/fixtures/ocr_audit_labels.json에는 육안 판독한 NASA 스캔 6~8쪽의
본문·여백 영역과 저작한 두 칼럼 래스터 6쪽의 영역이 들어 있다.
이 평가의 22개 영역, 662개 기준 단어에서는 누락 0개, 영역 안 단어
순서 불일치 0개, 표시되지 않은 여백 글자 0개, 쪽 밖 글자 0개,
겹친 OCR 줄 0쌍이었다.
이 수치는 라벨을 붙인 영역의 결과이며, 다른 쪽이나 전체 OCR 정확도,
번역 정확도를 보증하지 않는다.
기존 OCR에는 두 칼럼의 같은 높이 문장을 합친 줄과 인쇄되지 않은 ~~가
발견됐다. 줄을 칼럼별로 분리하고, 원본 픽셀이 흰 영역의 독립된 문장부호만
제외하도록 수정했다. 이 통제 쪽의 본문 블록 좌우 전환은 종전 3회에서
정상 순서인 1회로 줄었고, ~~ 세 곳은 새 입력에서 0곳이 됐다. 렌더링을
다시 확인했고 해당 여덟 라벨 영역의 단어 누락도 0개였다.
NASA 추가 스캔에서는 들여쓴 단일 칼럼을 두 칼럼으로 오인하고, 서로 이웃한
줄의 큰 OCR 상자를 한 줄로 합쳐 단어 순서를 뒤집었다. 순서에 민감한 검사를
추가해 기준 661단어의 순서 일치율이 처음 95.76%였던 것을 수정 후
100%로 확인했다. 검은 스캔 테두리·제본 구멍을 글자로 잘못 읽던 일부
여백 잡음도 원본 픽셀과 위치를 근거로 제외한다. 큰 OCR 글자 상자가
이웃 줄과 겹치던 사례는 주변 줄 간격에 맞춰 임시 입력 글자 크기를
제한해 복구했다. 이는 번역 전 입력 PDF의 조판 검사이며 최종 한국어
조판까지 보증하는 수치는 아니다.
기존 완료 작업의 Input.pdf와 번역 체크포인트는 그대로
두며, 새 작업의 OCR 결과에 이 수정이 적용된다.

표본을 추가할 때는 원본 페이지를 렌더링하여 사람이 보이는 단어와 해당 영역을
따로 기록한다. 원본 PDF 해시를 라벨에 묶고 이미지 안의 도표 글자와 본문을
혼동하지 않도록 영역을 좁힌다. 페이지 전체 OCR 재현율 또는 배치 정확도를
주장하려면 스캔 품질·단/표·회전·혼합 텍스트가 다른 독립 라벨을 더 모아야 한다.
