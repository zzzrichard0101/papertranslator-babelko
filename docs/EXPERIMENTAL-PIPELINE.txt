실험 파이프라인: 동시 검수 + 원문 용어 문맥 + 공간별 누락 추적
구현 날짜: 2026-10-22

사용
GUI의 '새 파이프라인 실험'을 선택하고 하이브리드 방식으로 새 작업을 시작한다.
CLI: python scripts/translate.py input.pdf --output 결과폴더 --mode hybrid --experimental-pipeline
기본은 해제되어 있다. 진행 중인 작업의 snapshot이나 번역 체크포인트를 자동 변경하지 않는다.
재개는 생성 당시 snapshot을 유지한다. 안정판으로 진행 중인 책을 비교 실험 때문에 실험판으로 전환하지 않는다.

1. 동시 검수
Qwen 두 요청이 모델 가중치를 공유한다. llama.cpp 총 문맥 16,384, 슬롯 2개로 각 요청의 문맥 8,192를 보존한다. KV는 기존 f16을 유지하고 MTP 정책도 같다. Hy 초벌은 기존 단일 슬롯이다.
검수 입력은 깊은 복사로 동결한다. 동시에 최대 두 그룹만 제출하며, 계산을 기다린 다음 원래 순서대로 메인 스레드에서 근거·통계·체크포인트를 저장한다. 후보 fingerprint가 바뀐 계산 결과는 버린다. 그룹 응답이 잘못되면 기존 문단별 검수를 수행한다. 취소·통신 오류를 통과 판정으로 처리하지 않는다.
모델 두 슬롯 적재 실패 시 엔진을 정리하고, 문맥을 줄이지 않은 단일 슬롯으로 재시도한다. 실패를 숨겨 병렬 성능으로 보고하지 않는다. GPU 외 프로세스와 모델을 공유하거나 종료하지 않는다.

2. 원문 용어 문맥
문서 분석 뒤 CPU에서 'evidence-based practice (EBP)' 같은 정확한 약어 정의를 수집한다. 참고문헌은 제외한다. 같은 약어가 서로 다른 의미로 정의되면 공통 힌트에서 제외한다.
현재 문단에 실제로 등장하는 약어만 최대 다섯 개, 제한된 길이로 초벌·재교정·검수 문맥에 넣는다. 출처 쪽과 정확한 원문 인용을 남긴다. 새 한국어 대응어를 추측해 전역 치환하지 않는다. 전체 번역 의미 검사는 그대로 유지한다.
해당 문단에 적용되는 정의·버전이 번역 키와 검수 fingerprint에 반영된다. 정의가 바뀐 문단은 예전 의미 판정을 재사용하지 않는다. document-context.json은 로컬 작업 폴더에만 저장한다.
이 기능은 원문 약어 문맥이며, 모든 전문용어의 자동 한국어 용어집이나 문서 전체의 지시대명사 해결 기능은 아니다.

3. 공간별 출처 장부
분석된 원문 문단마다 원문 쪽·좌표·역할·본문과 중복 순번을 묶어 occurrence ID를 만든다. 같은 문장이 다른 셀/쪽에 있어도 개별 항목으로 남는다. 번역 캐시의 내용 키는 별도로 공유할 수 있다.
최종 replay에서 문단 입력과 실제 반환 번역이 맞는 모델 기록을 연결한다. 원문 준비 작업과 추론 작업이 다른 스레드에서 실행되는 native batch도 지원한다.
조판이 끝난 글자 좌표를 기록하고, 최종 PDF에서 각 글자가 같은 위치에 남았는지 한 번씩 소비하며 비교한다. 짧은 숫자/중복 셀도 검사한다. 분석된 영어 본문이 번역에 제출되지 않음, 모델 기록 연결 누락, 조판 중 글자 유실, 출력 중 유실·위치 변경은 완료를 차단한다. 참고문헌 보존은 별도 정책으로 기록하며 글자 잔존은 계속 확인한다.
출력: region-ledger.json, region-coverage.json, Quality.json의 region_coverage.
이 장부는 분석 이후부터의 추적이다. OCR이 처음부터 읽지 못한 글자, 의미적 오역, 읽기 순서, native 조판 계획 자체가 원문과 완벽하게 같은지는 별도의 검사 대상이다. '무오류 보장'으로 해석하지 않는다.

검증 도구
pytest: 동시 실행·순서·입력 불변·취소·오래된 결과 거부, 약어 충돌·키 변경, 중복 셀 유실·이동·번역 전 누락·스레드 간 연결 검사.
python scripts/integration.py --mode hybrid --experimental-pipeline --diverse
실제 native 분석/OCR/조판과 결정적인 가짜 로컬 모델로 2칼럼, 스캔, 표, 참고문헌, 가로·회전 쪽을 검사한다. 가짜 모델의 한국어는 의미 품질 평가에 사용하지 않는다. 재개 시 요청·모델 로딩 0회와 텍스트·좌표·렌더 픽셀 동일성을 검사한다. 전체 글자 유실과 짧은 표 셀 이동을 주입해 완료 거부도 확인한다.
python scripts/benchmark_execution.py --job 작업폴더 --output test_vault/새비교폴더
동일 Qwen으로 단일/동시/동시/단일 ABBA를 실행한다. 독립 작성 대조군과 기존 모델 통과 장문을 구분하고 전체 응답을 로컬에 보존한다. --pause-job는 해당 앱 작업의 소유권을 확인해 중단·백업하고 finally에서 원래 설정으로 재개한다. 사용자가 이미 취소한 작업은 자동 재개하지 않는다.
ABBA는 검수 부하 측정이며 책 전체 시간의 직접 비교가 아니다. 캐시·재교정량·초벌·OCR·모델 적재 비중에 따라 전체 이득이 달라진다. 부정·조건·주체 반전 등의 미탐과 정상문장 오탐을 같이 확인한다.

2026-10-22 실제 로컬 측정
같은 Qwen 27B Q4_K_M, llama.cpp b11718, MTP, f16 KV, 요청당 8,192 문맥, RTX 4090에서 단일→동시→동시→단일 순서로 측정했다. 실행 중이던 책을 중단·백업하고 GPU를 격리했으며 비교 후 원래 작업을 자동 재개했다.
독립 작성 정상/오류 대조 26개 + 기존 모델 통과 장문 4개 = 30개 기록을 사용했다. 장문 네 개는 독립 정답으로 간주하지 않았다.
단일 슬롯 두 회: 39.013초 / 38.581초, 중앙값 38.797초.
동시 두 슬롯 두 회: 31.094초 / 31.112초, 중앙값 31.103초. 검수 부하 시간 19.83% 감소.
각 회 16요청, 입력 17,983토큰으로 같았다. 출력은 단일 3,417 / 동시 3,438토큰이었다. 고정 정상/오류 대조군은 네 회 모두 26/26, 장문 재검사 결과 변화도 없었다. 모델 응답이 동일한 바이트라는 뜻은 아니다.
관측 최대 GPU 메모리: 단일 20,279MiB / 동시 21,192MiB. 메모리는 GPU 전체 사용량이므로 데스크톱 등의 영향도 포함한다.
개별 요청 p95는 단일 약 3.8~3.9초 / 동시 약 5.0초로 늘지만, 두 요청을 겹쳐 전체 검수 부하는 빨리 끝났다. 모델 적재는 각 회 약 16초로 검수 시간에서 분리했다.
이는 검수 단계의 유의미한 속도 개선 실측이며, 전체 문서 처리 시간 19.83% 감소나 모든 문서의 동일 정확도 보장이 아니다. 책 전체 중앙 시간 15% 감소라는 기본판 승격 기준은 아직 측정하지 않았으므로 실험 옵션으로 유지한다.
원시 입력·모델 응답·수치·피크 메모리는 로컬 test_vault에 보존하고 공개 소스에 넣지 않는다.

아직 기본판에 추가하지 않은 후보
MetricX 같은 독립 QE는 문서·한국어 영역별 보정과 별도 의존성/가중치 준비가 필요하다. 현재 모델 검수를 생략하는 기준으로 넣지 않았다. TranslateGemma나 새 OCR로 전면 교체한 것도 아니다. 후보 자료와 채택 기준은 OPTIMIZATION-RESEARCH.txt에 기록되어 있다.
